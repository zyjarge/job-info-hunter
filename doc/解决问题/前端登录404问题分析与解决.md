# 前端登录 404 问题分析与解决

## 问题描述

在实现前端登录功能时，遇到了 404 错误。具体表现为：
1. 用户访问 `http://localhost:3000`
2. 自动跳转到登录页面 `http://localhost:3000/auth/login`
3. 输入用户名密码后，发送登录请求时返回 404 错误

错误信息依次演变：
```
POST /api/v1/auth/login 404 in 78ms
POST /token 404 in 55ms
POST /api/v1/token 404 in 45ms
```

## 问题分析

通过错误信息的演变，我们可以看到问题的关键在于：

1. 前端请求 URL 的构建方式不正确
2. 没有考虑前后端分离架构下的完整 URL 问题
3. 相对路径导致请求发送到了前端服务器而不是后端 API

主要原因是：
- 前端运行在 `http://localhost:3000`
- 后端 API 运行在 `http://localhost:8000`
- 使用相对路径会导致请求发送到前端服务器

## 解决方案

### 1. 添加后端 API 基础地址配置

在 `src/lib/api/auth.ts` 中：
```typescript
const API_BASE_URL = "http://localhost:8000";

export async function login(data: LoginRequest): Promise<LoginResponse> {
    const formData = new FormData();
    formData.append("username", data.username);
    formData.append("password", data.password);
    
    const response = await axios.post<LoginResponse>(
        `${API_BASE_URL}/api/v1/token`, 
        formData,
        {
            headers: {
                "Content-Type": "multipart/form-data",
            },
        }
    );
    return response.data;
}
```

### 2. 更新拦截器配置

在 `src/lib/api/interceptor.ts` 中：
```typescript
const API_BASE_URL = "http://localhost:8000";

const api = axios.create({
    baseURL: API_BASE_URL + "/api/v1",  // API 请求的基础路径
    timeout: 60000,
});
```

## 关键点总结

1. 前后端分离架构中，需要明确：
   - 前端服务器地址和端口
   - 后端 API 服务器地址和端口
   - API 的基础路径

2. API 请求 URL 构建：
   - 使用完整的 URL（包含协议、主机名、端口）
   - 统一的 API 基础路径配置
   - 正确的请求路径拼接

3. 请求格式：
   - 登录请求使用 FormData 格式
   - 设置正确的 Content-Type
   - 符合后端 API 的要求

## 最佳实践建议

1. 环境配置：
   - 使用环境变量配置 API 地址
   - 区分开发和生产环境
   - 统一的配置管理

2. API 请求封装：
   - 使用 axios 实例
   - 统一的拦截器配置
   - 错误处理机制

3. 开发调试：
   - 使用浏览器开发者工具查看网络请求
   - 检查请求 URL、方法、头部和数据
   - 查看后端日志定位问题
