# 调度系统使用手册

## 1. 项目结构
```
projects/scheduler/
├── api/                    # API相关代码
│   ├── routes.py          # API路由定义
│   └── schemas.py         # 请求/响应数据模型
├── conf/                   # 配置文件
│   └── config.py          # 系统配置
├── core/                   # 核心功能
│   └── scheduler.py       # 调度器核心实现
├── models/                # 数据库模型
│   ├── base.py           # 数据库连接配置
│   └── job.py            # 数据模型定义
├── logs/                  # 日志文件目录
├── main.py               # 应用入口
├── requirements.txt      # 依赖包列表
└── Dockerfile           # Docker构建文件
```

## 2. 代码职责说明

### 2.1 核心组件
- `main.py`: 应用程序入口，负责初始化FastAPI应用和数据库
- `core/scheduler.py`: 调度器核心实现，包含任务管理和执行的主要逻辑
- `api/routes.py`: API路由定义，处理HTTP请求
- `api/schemas.py`: 定义API的请求和响应数据模型
- `models/job.py`: 定义数据库模型
- `conf/config.py`: 系统配置，包含数据库、MQ等配置项

### 2.2 数据库结构

#### SchedulerJob 表
| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | Integer | 主键 |
| name | VARCHAR(255) | 任务名称 |
| description | VARCHAR(1000) | 任务描述 |
| cron_expression | VARCHAR(100) | cron表达式 |
| job_params | JSON | 任务参数 |
| is_active | Boolean | 是否激活 |
| created_at | DateTime | 创建时间 |
| updated_at | DateTime | 更新时间 |

#### JobExecutionHistory 表
| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | Integer | 主键 |
| job_id | Integer | 任务ID |
| start_time | DateTime | 开始时间 |
| end_time | DateTime | 结束时间 |
| status | VARCHAR(20) | 执行状态 |
| result | JSON | 执行结果 |
| error_message | VARCHAR(1000) | 错误信息 |

## 3. 部署和运行

### 3.1 启动服务
```bash
# 1. 启动基础设施（Elasticsearch和RabbitMQ）
cd docker
docker-compose -f docker-compose-infra.yml up -d

# 2. 启动调度器服务
docker-compose -f docker-compose-scheduler.yml up -d
```

### 3.2 停止服务
```bash
# 停止调度器服务
docker-compose -f docker-compose-scheduler.yml down

# 停止基础设施
docker-compose -f docker-compose-infra.yml down
```

## 4. API接口说明

### 4.1 接口列表
- `POST /api/v1/jobs/`: 创建新任务
- `GET /api/v1/jobs/`: 获取所有任务
- `GET /api/v1/jobs/{job_id}`: 获取特定任务详情
- `PUT /api/v1/jobs/{job_id}`: 更新任务
- `DELETE /api/v1/jobs/{job_id}`: 删除任务
- `POST /api/v1/jobs/{job_id}/pause`: 暂停任务
- `POST /api/v1/jobs/{job_id}/resume`: 恢复任务
- `GET /api/v1/jobs/{job_id}/history`: 获取任务执行历史

### 4.2 接口测试方法

#### 创建任务
```bash
curl -X POST "http://localhost:8000/api/v1/jobs/" \
-H "Content-Type: application/json" \
-d '{
  "name": "数据工程师职位爬取",
  "description": "定期爬取数据工程师的职位信息",
  "cron_expression": "*/5 * * * *",
  "job_params": {
    "job_title": "数据工程师",
    "city": "北京",
    "site": "liepin",
    "keywords": ["数据工程师", "ETL", "数据仓库"]
  }
}'
```

#### 查看所有任务
```bash
curl "http://localhost:8000/api/v1/jobs/"
```

#### 查看特定任务
```bash
curl "http://localhost:8000/api/v1/jobs/1"
```

#### 暂停任务
```bash
curl -X POST "http://localhost:8000/api/v1/jobs/1/pause"
```

#### 恢复任务
```bash
curl -X POST "http://localhost:8000/api/v1/jobs/1/resume"
```

#### 修改任务
```bash
curl -X PUT "http://localhost:8000/api/v1/jobs/1" \
-H "Content-Type: application/json" \
-d '{
  "cron_expression": "0 */1 * * *",
  "job_params": {
    "job_title": "数据工程师",
    "city": "上海",
    "site": "liepin",
    "keywords": ["数据工程师", "大数据"]
  }
}'
```

#### 查看任务执行历史
```bash
curl "http://localhost:8000/api/v1/jobs/1/history"
```

#### 删除任务
```bash
curl -X DELETE "http://localhost:8000/api/v1/jobs/1"
```

## 5. Cron表达式说明
- `*/5 * * * *`: 每5分钟执行一次
- `0 * * * *`: 每小时整点执行
- `0 0 * * *`: 每天零点执行
- `0 */2 * * *`: 每2小时执行一次
- `0 9 * * 1-5`: 工作日上午9点执行

## 6. APScheduler 操作指南

### 6.2 任务状态字段说明
- `id`: APScheduler 中的任务 ID
- `name`: 任务名称
- `func`: 执行的函数名
- `args`: 位置参数列表
- `kwargs`: 关键字参数字典
- `trigger`: 触发器信息
  - `type`: 触发器类型（如 CronTrigger）
  - `expression`: 触发器表达式
  - `next_run_time`: 下次触发时间
  - `timezone`: 时区信息
- `next_run_time`: 下次执行时间
- `pending`: 是否处于等待状态
- `paused`: 是否已暂停

### 6.3 任务管理最佳实践
1. 创建任务时设置合理的 cron 表达式，避免任务执行过于频繁
2. 使用任务暂停功能而不是删除任务，以便需要时可以恢复
3. 定期检查任务状态，确保任务正常运行
4. 使用任务执行历史来监控任务执行情况
5. 在更新任务时注意保持任务参数的一致性

### 6.4 错误处理
常见错误响应：
1. 调度器未初始化
```json
{
    "detail": "调度器未初始化"  // 500
}
```

2. 任务未找到
```json
{
    "detail": "APScheduler 中未找到该任务"  // 404
}
```

3. 任务执行失败
```json
{
    "detail": "任务执行失败"  // 500
}
```

### 6.5 监控建议
1. 定期检查 APScheduler 中的任务状态
2. 监控任务的 `next_run_time` 确保正常调度
3. 关注 `paused` 状态，避免任务意外暂停
4. 检查任务执行历史中的错误信息
5. 监控数据库和消息队列的连接状态
